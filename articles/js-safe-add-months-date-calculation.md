「入社日から6か月後」「契約日から1年後」のように、日付に月単位で加算した日付を求める処理は業務系ツールで頻出します。JavaScriptの`Date`には月を直接足せるメソッドがあるので一見簡単そうですが、素朴に実装すると月末日の入力で必ず壊れます。有給休暇の付与日を計算するツールを作る際にこの実装を詰めたので、パターンとして整理します。

## 素朴な実装が壊れるケース

`Date.setMonth()`は「今の月+n」を渡せば月を進めてくれるので、こう書きたくなります。

```js
// 一見動きそうだが、月末日の入力で壊れる実装
function addMonthsNaive(date, months) {
  const d = new Date(date.getTime());
  d.setMonth(d.getMonth() + months);
  return d;
}
```

これを2023年8月31日に「6か月後」で試すと、`setMonth`は2024年2月に月だけを進めた上で「31日」をそのまま維持しようとします。しかし2024年は うるう年でも2月は29日までしかないため、日付は繰り上がって**2024年3月2日**になってしまいます。「6か月後」のつもりが、2月をまるごと飛び越えて3月にずれるわけです。

月末日(28〜31日)を起点にした月加算では、加算先の月がそれより日数の少ない月(2月や30日までの月)になるたびにこの繰り上がりが起こります。入社日・契約日はユーザーの入力に依存するため、月末日を除外することはできません。

## 対処: 1日にリセットしてから加算し、あとで日をクランプする

繰り上がりが起きるのは「まだ存在しない日付(2024年2月31日など)」を`Date`に渡してしまうためです。対策は、月を加算する間は日を1日に固定して繰り上がりを起こさせず、月が確定したあとで加算先の月の実際の日数と比較して日を丸める、という2段階に分けることです。

```js
function addMonthsSafe(date, months) {
  const d = new Date(date.getTime());
  const day = d.getDate();

  d.setDate(1);                      // 繰り上がりを起こさせないよう1日に退避
  d.setMonth(d.getMonth() + months); // 月だけを安全に加算

  // 加算先の月の末日を求め、元の日をその範囲にクランプする
  const daysInTargetMonth = new Date(d.getFullYear(), d.getMonth() + 1, 0).getDate();
  d.setDate(Math.min(day, daysInTargetMonth));

  return d;
}
```

ポイントは`new Date(year, month + 1, 0)`という書き方です。JavaScriptの`Date`コンストラクタは日に`0`を渡すと「指定した月の前日」、つまり対象月の末日を返します。これを使えば、加算先の月が28日までしかないのか31日まであるのかを、うるう年判定を自前で書かずに求められます。

先ほどの例(2023年8月31日 + 6か月)で検証すると、1日にリセットしてから6か月進めると2024年2月1日になり、2月の末日を`new Date(2024, 2, 0).getDate()`で求めると29日(うるう年)、`Math.min(31, 29)`で29日にクランプされて**2024年2月29日**が正しく得られます。

## 検証すべき境界値

この実装を業務ツールに組み込む際は、少なくとも次のパターンをテストしておくと安心です。

- **月末日 + 平年2月をまたぐ加算**(例: 1月31日 + 1か月 → 2月28日)
- **月末日 + うるう年2月をまたぐ加算**(例: 2023年8月31日 + 6か月 → 2024年2月29日)
- **30日までの月をまたぐ加算**(例: 3月31日 + 1か月 → 4月30日)
- **年をまたぐ加算**(例: 11月30日 + 3か月 → 翌年2月末日相当)

いずれも「加算先の月に、元の日がそのまま存在するとは限らない」という同じ原因から来る境界値なので、この4パターンを手計算値と突き合わせておけば大きな漏れはありません。

## まとめ

- `date.setMonth(date.getMonth() + n)`だけの実装は、月末日を起点にすると存在しない日付への繰り上がりで壊れる
- 対策は「1日に退避してから月を加算し、加算先の月の実際の日数にクランプする」の2段階
- `new Date(year, month + 1, 0).getDate()`で、うるう年判定を自前で書かずに対象月の日数を取得できる
- 月末日・うるう年2月・30日月・年またぎの4パターンは境界値として必ず手計算値と照合する

入社日・契約日・更新日など「基準日から n か月後」を扱う業務ツールは多いので、この2段階の実装パターンはそのまま流用できます。
