GitHub Actionsの`schedule`やLinuxの`crontab`で、日付を指定するときに次のような式を書いたことはないでしょうか。

```
0 9 15 * 1
```

「毎月15日、かつ月曜日」のつもりで書くと、意図と違う動きに驚くことになります。cron式の5フィールド(分・時・日・月・曜日)のうち、「日」と「曜日」を両方とも `*` 以外の値にした場合の挙動は、標準cron仕様では **AND ではなく OR** だからです。

個人開発で「Cron式 次回実行日時計算ツール」(現在ステージング中で近日公開予定)を実装する過程でこの仕様の実装を詰めたので、挙動と実装方法を整理します。

## 何が起きるか

先ほどの `0 9 15 * 1` は、次のどちらの条件も満たす日に実行されます。

- 毎月15日(曜日を問わず)
- 毎週月曜日(日付を問わず)

つまり「15日かつ月曜日」ではなく「15日、または月曜日」です。今月15日が水曜日でも実行されますし、15日でなくても月曜日なら毎週実行されます。「毎月15日の月曜だけ動かしたい」という意図で書くと、想定より遥かに高い頻度で実行されてしまいます。

これはPOSIX cronの仕様([`crontab(5)`](https://man7.org/linux/man-pages/man5/crontab.5.html))に明記されている挙動で、GitHub Actions・Linuxのcrond・多くのジョブスケジューラが同じ解釈を採用しています。バグではなく仕様です。

## なぜANDにならないのか

歴史的な経緯まではman pageには書かれていませんが、実務上ハマりやすいポイントは「`*` は『条件なし』であって『AND対象から除外』という意味ではない」ことです。日フィールドが `*` のとき、それは「日は問わない」という意味なので、曜日条件だけで判定されます。逆に曜日フィールドが `*` のときも同様です。両方とも `*` 以外を指定した瞬間、「どちらか片方が条件なしではなくなる」のではなく、「両方とも有効な条件として、OR で合成される」という仕様になっています。

## 実装する場合の分岐

自分で次回実行日時を計算するロジックを書く場合、次のように分岐させる必要があります。

```js
function matchesDate(date, dayOfMonthField, dayOfWeekField) {
  const domIsWildcard = dayOfMonthField === '*';
  const dowIsWildcard = dayOfWeekField === '*';

  if (domIsWildcard && dowIsWildcard) {
    return true; // 両方 * なら日付条件なし
  }
  if (domIsWildcard) {
    return matchesDayOfWeek(date, dayOfWeekField);
  }
  if (dowIsWildcard) {
    return matchesDayOfMonth(date, dayOfMonthField);
  }
  // 両方とも指定済み → OR
  return matchesDayOfMonth(date, dayOfMonthField) || matchesDayOfWeek(date, dayOfWeekField);
}
```

ここで気をつけるべきは、単純に「両方チェックしてAND」と書いてしまうテストが一見通ってしまう点です。`* * 15 * 1` のようなワイルドカードを含まないテストケース(例えば「日と曜日を両方具体的な値にして、その組み合わせの日だけ一致するか」)だけでは、ANDで実装してもたまたま該当日に一致してしまうことがあります。検証には、次のようなケースを必ず含める必要があります。

- 日フィールドだけ指定・曜日は`*`(単純な日付条件として動くか)
- 曜日フィールドだけ指定・日は`*`(単純な曜日条件として動くか)
- **両方とも具体的な値を指定し、日付条件を満たすが曜日条件を満たさない日**が候補に含まれるか(ORでないと漏れる)
- 両方とも具体的な値を指定し、曜日条件を満たすが日付条件を満たさない日が候補に含まれるか

最後の2つを手計算で用意し、実装結果と突き合わせるまでは「ANDで書いたバグ」に気づけません。実際、この仕様を知らずにANDで実装し、狙った日にジョブが動かなかったという事例はGitHub ActionsやJenkinsのIssueトラッカーでも度々見かけます。

## 曜日番号の0と7

余談ですが、曜日フィールドは `0`(日曜)〜`6`(土曜)に加えて `7` も日曜として扱われる実装が一般的です(cronの仕様上、0と7はどちらも日曜)。次回実行日時を計算するツールを自作する場合は、`7` を `0` に正規化してから比較するとハマりません。

## まとめ

- cron式で「日」と「曜日」を両方とも `*` 以外にすると、AND ではなく **OR** になる
- 「毎月N日の特定曜日だけ」を表現したい場合は、この仕様では直接書けない(シェルスクリプト側で曜日をさらに絞り込むなど、別の手段が必要)
- 自分で判定ロジックを書く場合は、両フィールドがワイルドカードかどうかで4パターンに分岐させる
- テストには「日付条件は満たすが曜日条件は満たさない日」を必ず含める

GitHub Actionsのスケジュールは分単位まで作り込んでも、UTC評価であることも含めて誤解しやすいポイントが多い領域です。以前書いた[Claude CodeのRoutines設定ガイド](https://zenn.dev/ykwlab/articles/claude-code-routines-guide)でもUTC評価と最小間隔の注意点をまとめているので、あわせて参考にしてください。
