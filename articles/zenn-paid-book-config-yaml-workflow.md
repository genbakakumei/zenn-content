## この記事について

ZennはGitHubリポジトリと連携すると、記事だけでなく**本(book)**もリポジトリのファイルだけで管理・公開できます。本の実体は「章ごとのMarkdownファイル + 1つの `config.yaml`」というシンプルな構成で、Zenn上でGUI操作する場面はほとんどありません。

筆者はAIエージェント(Claude)に定期実行での自律運営を任せる個人開発の実験の一環で、有料本を1冊(全8章)GitHub連携だけで書き上げて公開しました。この記事では、そのときに実際に使った運用パターンを、特定のツールや事業の詳細を離れて一般化して解説します。「Zennで本を出したいが構成の作り方がわからない」「本を書きながら価格や公開状態を試行錯誤したい」という方向けの内容です。

## 本の最小構成

Zennの本は、リポジトリ内に次のような構造を置くだけで成立します。

```
books/
  your-book-slug/
    config.yaml
    01-introduction.md
    02-first-topic.md
    03-second-topic.md
```

`config.yaml` が本全体のメタデータと章順を持ち、各章は独立したMarkdownファイルです。この「メタデータと本文が分離している」構造が、後述する運用の柔軟さの土台になります。

```yaml
title: "本のタイトル"
summary: "本の要約(検索結果やOGPに使われる)"
topics: ["ai", "個人開発"]
published: true
price: 1000
chapters:
  - 01-introduction
  - 02-first-topic
  - 03-second-topic
```

章ファイル側のfrontmatterは章タイトルだけを持たせるのが基本形です。

```markdown
---
title: "第1章 はじめに"
---

本文...
```

## config.yamlひとつで制御できること

### 1. 公開状態(published)を執筆中と刊行後で切り替える

`published: false` にしておけば、章をどれだけ書き足してもリポジトリにpushするだけで、Zenn上では非公開のまま蓄積できます。全章の初稿が揃ってから `published: true` に切り替えてpushする、という運用にすると、「章立てはリポジトリで育てながら、公開は一度きりのイベントにする」という切り分けができます。

これは複数人での査読フローとも相性がよく、`published: false` のプルリクエストをレビューしてからマージ→公開、という流れも組めます。

### 2. 価格(price)は公開後も変更できる

`price` はただの数値フィールドなので、初期価格を仮決めして公開し、売上データを見てから改定する、という運用が可能です。価格変更のためにZennの管理画面を操作する必要はなく、`config.yaml` の1行を変えてpushするだけです。

### 3. 章の並び替え・差し替えが配列の編集だけで完結する

`chapters` は単なる文字列配列なので、章の順序変更や、公開後に章を1つ追加する場合も、この配列を編集してファイルを追加するだけです。目次の構造がYAMLのリストとして明示されているため、「今どういう章立てになっているか」をコードレビューの感覚で確認できます。

## 無料プレビュー章(free)で導線を作る

章ファイル側のfrontmatterに `free: true` を追加すると、その章だけを無料プレビューとして開放できます。

```markdown
---
title: "第1章 はじめに"
free: true
---
```

購入前に本のトーン・粒度・実際に得られる情報の解像度を確認してもらえるため、「買ってみたら期待と違った」というミスマッチを減らせます。第1章(導入・全体像)を無料にし、具体的な実装パターンが始まる第2章以降を有料にする、という切り方が素直で使いやすい構成です。

無料化する章は後から変更可能なので、「最初は第1章だけ無料にしておき、反応を見て第2章も無料に広げる」といった調整もできます。

## 章ファイル単位の管理が効く理由

本全体を1つの巨大なファイルにせず、章ごとにファイルを分けておくメリットは、GitHub連携ならではの形で効いてきます。

- **差分レビューが章単位になる**: 1章だけ加筆・修正したコミットは、その章のファイルだけを変更する差分になるため、変更内容が把握しやすくなります
- **執筆途中の章と完成した章が共存できる**: `published: false` の間は、内容が薄い章(スタブ)と完成稿が混在していても問題ありません。全体が完成してから公開に切り替えれば、読者には完成形しか見えません
- **誤字修正が独立した小さなコミットになる**: 公開後に見つかった誤字も、該当章のファイルだけを直す小さなコミットで対応でき、他の章に影響しません

## まとめ

- Zennの本は「章ごとのMarkdown + config.yaml」というシンプルな構成で、GUI操作なしにGitHubだけで完結して運用できる
- `published` で執筆中と刊行後を切り替え、`price` は公開後も改定でき、`chapters` の配列編集だけで目次を管理できる
- 章のfrontmatterに `free: true` を足すだけで無料プレビュー章を作れ、購入前の期待値調整に使える
- 章ファイルを分けておくことで、差分レビュー・部分的な修正・執筆途中と完成稿の共存がしやすくなる

技術書に限らず、継続的に加筆・改訂したいドキュメントをGitHubで管理したい場合には、このパターンはZenn以外の場面でも応用できる考え方だと思います。
