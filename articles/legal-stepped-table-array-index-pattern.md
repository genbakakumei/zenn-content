有給休暇の付与日数、所得税の税率、介護保険料率など、「勤続年数」や「所得階層」が一定のしきい値を超えるたびに段階的に値が変わる数表は、法律・制度まわりのツールを個人開発していると頻繁に出てきます。この手の数表を素朴に実装すると、しきい値ちょうどの境界で1件だけ値がズレるバグを作り込みやすい領域です。実際に有給休暇計算ツールを実装したときに固めた、境界条件に強い書き方を整理します。

## 素朴に書くと境界で壊れやすい理由

「勤続年数が1年6ヶ月以上なら11日、2年6ヶ月以上なら12日」という仕様をそのまま `if/else if` の階段で書くと、一見自然に見えます。

```js
// やりがちな実装
function grantDays(years) {
  if (years >= 6.5) return 20;
  if (years >= 5.5) return 18;
  if (years >= 4.5) return 16;
  if (years >= 3.5) return 14;
  if (years >= 2.5) return 12;
  if (years >= 1.5) return 11;
  if (years >= 0.5) return 10;
  return 0;
}
```

この書き方の問題は、`years` を**日付の差分から計算した小数**で渡すと、うるう年・月末日の丸めの影響で「本来6.5年ちょうどのはずが6.499999...年と評価される」ようなケースが混入しうることです。しきい値比較は、入力が浮動小数点の日数差であるほど境界に弱くなります。さらに条件の並び順を1つ入れ替えるだけで全段が壊れる、しきい値を1つ追加するたびに全ての比較式を見直す必要がある、というメンテナンス性の問題も抱えます。

## 配列 + インデックスに変換する

実際の有給休暇計算ツールでは、「勤続年数で分岐する値」を比較演算ではなく、**「付与が何回目か」という整数インデックスの配列引き**に変換しています。

```js
const PERIOD_LABELS = ['6ヶ月', '1年6ヶ月', '2年6ヶ月', '3年6ヶ月', '4年6ヶ月', '5年6ヶ月', '6年6ヶ月以上'];
const FULL_TIME_DAYS = [10, 11, 12, 14, 16, 18, 20];
const PRO_RATA_DAYS = {
  4: [7, 8, 9, 10, 12, 13, 15],
  3: [5, 6, 6, 8, 9, 10, 11],
  2: [3, 4, 4, 5, 6, 6, 7],
  1: [1, 2, 2, 2, 3, 3, 3],
};

function daysForIndex(empType, idx) {
  const i = Math.min(idx, FULL_TIME_DAYS.length - 1); // 7回目以降は最終値に固定
  if (empType === 'full') return FULL_TIME_DAYS[i];
  return PRO_RATA_DAYS[empType][i];
}
```

付与日のスケジュールは「初回基準日から12ヶ月ごとに到来する」という**整数の繰り返し**なので、`i` 回目の基準日という整数インデックスは最初から確定しています(日付計算の丸め誤差が入り込む余地がない)。「勤続年数がいくつ以上か」を都度判定する代わりに、「ループの何周目か」をそのままキーにして数表を引くだけで済みます。しきい値比較そのものが式から消えるため、境界条件のバグが原理的に発生しません。

7回目以降は日数が据え置きになる(労基法39条の原則表は6年6ヶ月以上で20日固定)仕様も、`Math.min(idx, 配列の最後の添字)` という1行のclampで表現でき、「無限に続く仕様」を「有限配列+clamp」という扱いやすい形に落とし込めます。

## この設計が効く条件

この変換が成立するのは、**しきい値の刻み幅が一定**(今回は12ヶ月ごと)で、かつ**インデックスが浮動小数点の計算結果ではなく整数カウンタとして得られる**場合です。刻み幅が不揃いな数表(例: 所得税の累進税率のように階層の幅がバラバラ)の場合は配列引きではなく、しきい値の配列を昇順に並べて `Array.prototype.findIndex` で該当区間を探す方式が素直です。いずれにしても、「比較演算を都度書く」のではなく「数表をデータとして持ち、インデックスで引く」という方向に寄せておくと、しきい値が変わったとき(法改正等)も配列の値を差し替えるだけで追従できます。

## まとめ

- 段階的に増える法定の数表を `if/else if` の閾値比較で実装すると、浮動小数点の境界値でズレるバグを作り込みやすい
- 刻み幅が一定の数表は、しきい値比較ではなく「何回目か」という整数インデックスで数表配列を引く設計に変換できる
- 上限(据え置き)は `Math.min(idx, 配列長 - 1)` の1行で表現でき、「無限に続く仕様」を有限配列として扱える
